3]  *args:

Used for extra positional arguments.
Inside the function, args becomes a tuple.
Example meaning: if you pass 1, 2, 3, they are collected as args = (1, 2, 3).

**kwargs:

Used for extra keyword arguments.
Inside the function, kwargs becomes a dictionary.
Example meaning: if you pass name="Ava", age=20, they are collected as kwargs = {"name": "Ava", "age": 20}.


4]  decorator order
	Important point: the decorator written closest to the function runs first, but the top one wraps around it afterward.
       That is why the order matters when decorators print messages, measure time, or change function metadata.

7] GIL (Global Interpreter Lock) in Python

GIL is a lock in CPython that allows only one thread to execute Python bytecode at a time.

Why it exists:
- CPython uses reference counting for memory management.
- GIL simplifies internal object access and keeps interpreter behavior safe.

Important impact:
- CPU-bound pure Python threads do not run in true parallel on multiple cores.
- So multi-threading often does not speed up heavy Python loops.

Why this matters in ML:
- Data preprocessing, feature engineering, and custom Python-heavy transforms can become bottlenecks.
- This is one reason people say Python has limits for some ML workloads.

Why modern ML still scales:
- NumPy, PyTorch, TensorFlow, XGBoost run heavy compute in C/C++/CUDA.
- These libraries often release or bypass the GIL for compute-heavy operations.
- Multiprocessing and distributed systems use separate processes, each with its own GIL.

GIL vs async:
- Async/await is for concurrency during waiting (I/O-bound work).
- Async is not multi-core CPU parallelism.
- Async improves throughput for APIs, DB/network calls, and orchestration pipelines.

Rule of thumb:
- I/O-bound: use async or threading.
- CPU-bound: use multiprocessing, vectorized libraries, native extensions, or GPU.


8 ] app.state.model stores references to expensive shared resources rather than separate copies of those resources. Objects remain in memory as long as references to them exist. Python garbage collection removes objects only after all references disappear. In large AI systems, additional resources such as GPU memory, sockets, and database connections may exist outside normal Python memory management, requiring explicit cleanup during FastAPI lifespan shutdown procedures.
